# AI-03 · Build the complete PDF-to-filled-and-signed-PDF vertical slice

## Why

The first usable result is a PDF filled at the right coordinates and corrected/exported with the real editor, not a mock or a separate infrastructure layer.

## Scope and acceptance

- [x] Reuse Sign session/preview/manual controls/fonts/history/signature/PDF export as a second product island inside the existing Sign module with an optional AI panel/session seam; no cloned editor, sibling-tool imports or broad shared refactor.
- [ ] Open a PDF, analyze one selected page through live OpenAI, supply/paste facts, show missing answers, preview/apply editable text/check marks.
- [ ] Use existing detection where helpful plus vision for scans; validate bounded output and recorded image-to-PDF transforms/RTL placement.
- [ ] Values come from supplied facts; unresolved fields remain visible/manual; do not imply ChatGPT memory.
- [ ] Manual mode/error/cancel preserves accepted work and ignores stale responses; existing persistence is reused.
- [ ] One English and one Hebrew scanned example completes live analysis → correction → explicit signature → exported PDF in a browser.
- [x] Keep network/provider code isolated behind a small analyze-page function; no multi-provider framework, profiles or comprehensive field-map editor.

## Verified development checks (mocked provider)

- [x] Real English/Hebrew image-only PDF review/apply, manual correction and editable check movement.
- [x] Delete/Undo and explicit cancellation/manual continuation preserve applied work.
- [x] Explicit signature and real two-page PDF download, reopened/rendered with PDF.js; readable RTL checked.
- [x] Four existing Sign browser regressions and optional session-seam regression checks pass.
