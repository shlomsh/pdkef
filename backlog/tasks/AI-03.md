# AI-03 · Build the complete PDF-to-filled-and-signed-PDF vertical slice

## Why

The first usable result is a PDF filled at the right coordinates and corrected/exported with the real editor, not a mock or a separate infrastructure layer.

## Current scope: reusable semantic detector (2026-09-30)

User correction supersedes answer generation: send an original form page once for metadata;
PDkef fills, corrects, signs and exports locally without resubmitting user facts. The former
completed vertical slice is historical evidence below, not completion of this new architecture.

- [ ] Metadata-only provider contract: stable field IDs, label/section/semantic role, existing field kinds, bounded page geometry; no user facts or answer values sent/returned.
- [ ] Per-page map cached under original content-hashed document memory with schema/source-version invalidation and no second autosave writer.
- [ ] Optional cached `FieldSource` adapter / beta session seam retains ordinary Sign defaults and fuses local precise comb/checkbox geometry without losing semantic identity.
- [ ] Local per-field values or explicitly reviewed fact bindings keyed by field ID; duplicate labels in Employee/Employer sections remain distinct.
- [ ] Cached reopen, answer changes and export use zero additional inference; error/cancel/stale analysis preserves manual work and announces page/source changes beside Analyze instead of silently clearing review; timeout is explicit.
- [ ] One English and one Hebrew metadata-only map completes local filling/correction/explicit signature/export and PDF reopen/render checks; unsupported comb/office areas remain manual/blank appropriately.

Concrete contract/file sequence: [revised PRD](../../tasks/prd-ai-pdf-filler.md).

runner returned `connected:true` and an account-specific model catalog. Available
slugs were `gpt-6-astra`, `gpt-reserve`, `gpt-5.6-sol`, `gpt-5.6-terra`,
`gpt-5.6-luna`, `gpt-5.5`, and `codex-auto-review`; `gpt-6.1-sol` was absent.
One explicitly authorized request used ordinary `gpt-5.6-sol` with the original
1224 × 1584 first-page PNG and only `Name: Example Person`. No second inference,
credential borrowing, account history, annotations or signatures were sent.

`store:false`, `stream:true`, inline image input and validated completed response
fields. It returned Name text at `(238,394,624,84)` with value `Example Person`, and
an unlabeled checkbox at `(238,632,44,45)` with null value. Its question was
“Should the unlabeled checkbox be checked or unchecked?” The name matches supplied
facts; the checkbox remains unresolved; no signature/declaration or additional
personal fact was invented. The independently known printed Name rectangle is
`(240,396,620,80)`, giving box IoU approximately 0.946 on this single synthetic
example. This is not general accuracy evidence or proof of final answer placement.
