# MEM-20 · Each page's CSP hash list is emitted in a stable order

*Filed 2026-10-27* from the update-cost measurement after MEM-15..18.

## Why

- Every page carries a CSP meta whose `script-src` lists about 50 sha256 hashes, generated by Astro's
  `security.csp` (`astro.config.mjs:159`).
- Between two deploys of main (a8763091 to 7ffc926f) only five tool chunks were renamed (58 KB), yet all
  54 pages changed: 42 of them only in the CSP meta. On /compress/ the same 50-hash set appears with
  entries 26 and 27 swapped. That deploy cost a returning client 1,549,491 bytes (brotli q5).
- Since MEM-16 an unchanged page costs a 304, so an unstable order turns into a full download of every
  page. Where the order comes from is not traced yet.

## Outcome

- The hash list in each page's CSP is in a deterministic order (for example sorted), so two builds with
  the same set of hashes emit identical CSP metas.
- The fix sits where the list is produced or in one post-build step, not per page.

## Acceptance

- [ ] A test builds the same hash set in two different input orders and gets the same CSP meta.
- [ ] Rebuilding a8763091 and 7ffc926f leaves the 42 CSP-only page differences at zero.
- [ ] `npm run test:csp` stays green.
