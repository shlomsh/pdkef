# PE-08 · Scan opens a scanned PDF

*Opened 2026-11-04* from [the handoff](../../docs/scan-enhance-handoff.md), part of the page-enhancement plan.

**Route, decided by Shlomi 2026-11-04:** a crooked PDF is straightened in Scan and comes back to Highlight, not rebuilt inside Highlight. Squaring a page is not an affine move, so the vector rebuild this plan first had could not do it.

## Outcome

Scan takes a PDF as well as photos. Each sheet is drawn as an image, turned upright, and becomes one Scan page per book page, with the corners `planPage` found. The corners stay adjustable in Scan's corner editor; the app never asks for them page by page.

A spread's two pages share one sheet image and differ only in their corners, so `ScanPage` needs no new shape.

**Measured 2026-11-04, production build, Chromium and WebKit:** the book's 16 pages in about 5 s, built in about 10 s, 8 MB in Chromium.

## Acceptance

- [x] A PDF is accepted by pick and by drop; the camera input stays photos only.
- [x] pdf.js loads only when a PDF arrives: a photo scan ships no new bytes.
- [x] The book PDF's 8 sheets arrive as 16 pages, right page first (a right-to-left book), each sheet read once.
- [x] Found corners are not overwritten by Scan's edge guess; a corner the person moves wins.
- [x] A page with a text layer loses it in the output. That is accepted: the copy is an image and the original stays in recents.
- [ ] A protected PDF ends in the existing protected-file path, not a failure. Scan has none yet: today its name lands in the skipped-files notice, which needs Shlomi's call on wording or a detour through Unlock.
- [x] A remembered scan keeps its found corners after a reload (found corners count as settled).
- [x] A tilted sheet gets a white border, so every corner sits where the corner editor can reach it.
- [x] An e2e opens a two-page sheet fixture and sees two pages.
