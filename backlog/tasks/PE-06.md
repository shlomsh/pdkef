# PE-06 · Highlight: detect a crooked scan, no UI

*Opened 2026-11-04* from [the handoff](../../docs/scan-enhance-handoff.md), part of the page-enhancement plan.

## Outcome

Highlight reads a few pages of the file as it arrived and reports whether it is a crooked scan, silently. Pages render on the main thread, since pdf.js paints there, and `assess` runs in `enhance.worker.ts`.

## Acceptance

- [x] No marks needed and no visible change to the screen.
- [x] A crooked file is flagged; an upright scan and a born-digital PDF are not.
- [x] The check never blocks opening the file: it starts once the page is idle and loads as its own chunks.

## What counts as a scan

Sign's `PageKind` needs pdf-lib and reads page one only, and "no text" would miss the case this exists for: the book has
a full OCR layer, about 4500 characters over one image on every sheet. So a page is a scan when images cover at least
80% of it, read from pdf.js's operator list, with or without text on top. A born-digital file renders nothing.

## Production build, real browser, 2026-11-04

Each file opened in Highlight, verdict read from the `highlight_scan_check` event, about 1.5 to 1.9 s after opening.
The scans were made locally from book pages and are not in the repo.

| file | verdict |
|---|---|
| the book | spread |
| a born-digital PDF | straight, no worker started |
| upright scan | straight |
| scan lying sideways | sideways |
| scan leaning 3 degrees | lean |
