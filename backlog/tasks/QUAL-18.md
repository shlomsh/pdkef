# QUAL-18 · npm install in a fresh worktree leaves package-lock.json unchanged

Every fresh worktree's `npm install` rewrites package-lock.json, which then shows as a change and makes `check:fast` widen to the whole suite. Find the cause (npm version, optional platform packages, a missing field) and fix it at the source.

## Acceptance
- `git worktree add` then `npm install` leaves `git status` clean.

## Result

**Cause.** Not a fresh-worktree problem: two npm majors disagree about one metadata flag. Node 22 (CI, cloud sessions) ships npm 10.9.9; Node 24 (local, `npm --version` 11.8.0) ships npm 11. For the 27 optional `@img/sharp-*` platform packages (reachable from `astro` and from the dev-only `appium`), npm 10 writes `"dev": true` and npm 11 does not. Commit 40f4bc85 ("Refresh package-lock.json dev-flag metadata") had committed the npm 10 flavour, so every `npm install` on npm 11 removed those 27 lines. No version, resolved, integrity, lockfileVersion or root-name difference.

**Fix.** The lockfile is regenerated by a fresh npm 11 install (27 `"dev": true` lines removed, nothing else), and `package.json` gains `"packageManager": "npm@11.8.0"` so tools that honour it (corepack, Dependabot) generate the same flavour. CI keeps running `npm ci`, which never rewrites the lock and works with either flavour (verified on npm 10.9.9 and 11.8.0). A bare `npm install` on npm 10 still re-adds the 27 flags: use Node 24 / npm 11 for anything that writes the lockfile.

**Proof.** Fresh detached worktree from the fixed commit, `npm install` with npm 11.8.0: `git status` clean. `npm ci` passes on npm 10.9.9 and npm 11.8.0.
